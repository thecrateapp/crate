# Crate 3.1.0

Crate 3.1.0 makes an instance observable. System Health now says when its metrics are
incomplete instead of drawing them as healthy, the Stack page shows a live map of the
host and both deployments, and the optional Prometheus and Grafana stack deploys,
upgrades and rolls back on its own. The release also carries the server side of the
VirtualDJ integration that is still in development. It runs one database migration at
startup.

## Observability

- **Metrics you can trust in System Health.** Application metrics are stored per minute
  for eight days. Redis restarts, evictions and lost buffers are recorded as gaps next to
  the data, and each figure says whether it is live, persisted, partial or stale. A
  missing value is shown as missing, not as zero.
- **A live map on the Stack page.** The host, the application and the monitoring stack
  appear as one topology map. While the page is open it shows requests per minute by
  client (Listen on web, Android, iOS and desktop, Admin, Subsonic), tasks per queue,
  projected events and devices listening now. With monitoring enabled it adds CPU and
  memory per service and, when Traefik exposes its metrics, requests through Edge. The
  map only carries counts, stops when nobody watches and respects reduced motion.
- **Monitoring as its own deployment.** Prometheus, Grafana and the exporters run as the
  `crate-observability` Compose project. `make observability-deploy VERSION=<sha>` ships
  only revisions from `main`, restarts only the services that changed and rolls back by
  itself if scrapes or Grafana do not verify. Prometheus and Grafana data is copied
  before an image upgrade and restored if it fails. Installations running the earlier
  monitoring overlay move to the new project with `make observability-adopt`, keeping
  their history and dashboards. Grafana stays on the server's loopback; reach it through
  an SSH tunnel.
- **One deploy at a time.** Application, Crate Operator and monitoring deploys share a
  lease; a deploy that finds another one running changes nothing. A lease left by an
  interrupted deploy is released with `make deploy-unlock`.
- **Infrastructure dashboards.** Grafana provisions host and container, and PostgreSQL
  and Redis dashboards. Sentry releases now follow each image's source revision.

## VirtualDJ (in development)

The VirtualDJ plugin is not distributed yet. The server already supports it:

- Search accepts DJ filters such as `artist:"…"`, `album:"…"` and `bpm:120-128` in the
  query text.
- Compatible tracks carry duration, BPM, Camelot key, energy, year, genre and artwork
  from the Smart Mix analysis.
- Stream tickets for access tokens last 12 hours, so tracks queued by automix keep
  playing.

## Upgrading

- The migration that creates the metric history runs automatically when the API starts.
- Crate Operator hosts take part in the deploy lease once their `deploy-remote.sh` and
  engine are reprovisioned.
- Monitoring stays optional. Enabling it, adopting the earlier overlay and turning on
  Traefik's metrics entrypoint are separate steps described in
  [Monitoring](https://docs.cratemusic.app/operations/monitoring).

## Downloads

- **Server:** `curl -fsSL https://cratemusic.app/install.sh | bash` for new home installs,
  or `crate install --dir <install folder>` to upgrade one. Binaries for Linux and macOS
  on amd64 and arm64 are attached, with `crate-checksums.txt`.
- **Desktop:** `Crate-macos-arm64.app.zip`, `Crate-macos-intel.app.zip`,
  `crate-windows.exe`, `crate-windows.msi`, `crate-linux.AppImage`, `crate-linux.deb` and
  `crate-linux.rpm`. Each is also at
  `https://github.com/thecrateapp/crate/releases/latest/download/<file>`. macOS builds
  are ad-hoc signed.
- **Android:** `crate.apk` (signed and minified), plus the versioned APK and App Bundle.
