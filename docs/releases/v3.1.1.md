# Crate 3.1.1

Crate 3.1.1 adds a Product page to Admin with daily figures for the whole instance,
an optional 3D view of the Stack map, and fixes that make the Stack map name the
real host and keep its monitoring readings across deploys. It runs one database
migration at startup.

## Product KPIs

- **A Product page in Admin.** Under Insights, the page compares the last 7, 30, 90
  or 365 days with the previous window: accounts and active accounts, daily, weekly
  and monthly listeners, signups and retention, plays, listening hours and sessions,
  library growth and the share of it played, acquisition outcomes per source,
  engagement, federation and streaming.
- **Computed off-request.** A maintenance task works out each day's figures every
  hour from the listening projections and small tables, and the page reads only the
  stored daily rows. On first run it backfills up to one year.
- **Private by default.** Breakdown segments backed by fewer than three listeners are
  hidden, free-text values are grouped as "other", and a source with no data shows as
  missing, not as zero. Every figure is defined on the docs site under Product KPIs.

## Stack map

- **3D view.** A 2D | 3D toggle on the Stack map shows each deployment as a dome with
  the same data, selection and live readings. Node size is memory and an outward
  spike is CPU. 2D stays the default; the choice is remembered, and the map falls
  back to 2D on narrow screens, without WebGL2 or when the GPU context is lost.
  Reduced motion turns off camera moves and particles. The 3D code loads only when
  the view is opened.
- **The real host name.** The map named the host after the API container's ID. It
  now asks the Docker daemon for the server's name unless `CRATE_HOST_NAME` is set,
  and `CRATE_HOST_ID`, `CRATE_HOST_NAME`, `CRATE_GRAFANA_URL` and
  `CRATE_OBSERVABILITY_PROJECT` set in `.env` now reach the API.
- **Monitoring readings survive deploys.** Application deploys ship the projector and
  Traefik monitoring overlays and keep each one while its monitoring network exists,
  so CPU, memory and Edge readings are no longer dropped by the next deploy.

## Upgrading

- The migration that creates the daily KPI table runs automatically when the API
  starts. The first KPI run backfills history in month-sized steps on the maintenance
  queue.
- Installations running monitoring as its own project set
  `OBS_PROMETHEUS_QUERY_NETWORK` and `OBS_TRAEFIK_METRICS_NETWORK` in the application
  `.env`, as described in
  [Monitoring](https://docs.cratemusic.app/operations/monitoring).

- **Desktop:** `Crate-macos-arm64.app.zip`, `Crate-macos-intel.app.zip`,
  `crate-windows.exe`, `crate-windows.msi`, `crate-linux.AppImage`, `crate-linux.deb` and
  `crate-linux.rpm`. Each is also at
  `https://github.com/thecrateapp/crate/releases/latest/download/<file>`. macOS builds
  are ad-hoc signed.
- **Android:** `crate.apk` (signed and minified), plus the versioned APK and App Bundle.
