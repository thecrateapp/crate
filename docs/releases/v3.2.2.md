# Crate 3.2.2

Crate 3.2.2 brings Sentry issues into Admin with a new Errors page, cuts error noise at
its source and fixes the library scan errors caused by albums indexed in two folders. It
has two database migrations, applied on upgrade.

Crate is published under the GNU Affero General Public License v3.0 (AGPL-3.0).

## Errors in Admin

- **A new Errors page** (System > Errors) lists the Sentry issues Crate syncs every 5
  minutes, ordered by a Crate priority score. Issues scoring 70 or more form a critical
  lane at the top, duplicates with the same exception and failing frame collapse into
  one row, and filters by lane, status, service, class and release stay in the address.
- **Issue detail** shows counts, first and last seen, releases, the exception chain, the
  application frames with the source lines Sentry stored, allowlisted tags and recent
  breadcrumbs. The page only reads Crate's database, so a slow Sentry never slows it.
- **Resolve in next release, Ignore until escalating and Reopen** change the issue in
  Sentry from Crate. They need a token with Issue & Event write access; with a
  read-only token the inbox works and hides them.
- **The Sentry connection** lives in a drawer opened from the page header: base URL
  (`sentry.io`, `us.sentry.io`, `de.sentry.io` or a self-hosted address), organization,
  projects, environments and the token of a Sentry internal integration, stored
  encrypted. _Test connection_ checks the token from a worker.
- **System Health** gains an Errors tile with open, critical, new and regressed issues
  of the last 24 hours and the top of the critical lane.
- **Crate Agent and Crate Operator** can read the inbox through three read-only MCP
  tools, `get_error_summary`, `list_error_issues` and `get_error_issue`, under the new
  `ops.errors.read` grant. The Crate Agent and Crate Operator presets include it.
- Nothing runs until a connection is saved. [Observability](https://docs.cratemusic.app/operations/observability)
  covers the setup.

## Less noise in Sentry

- Rate-limited calls to metadata providers, offline and aborted requests in the web
  apps, and stale frontend bundles no longer open issues. Gateway errors in front of the
  API (502–504 and 520–524) group into one "API unavailable" issue per app.
- Worker events no longer carry local variables, and fields named `key` are redacted.
- Failures the Errors page already explains, such as a rejected token, a wrong
  organization or Sentry being down, are not reported to Sentry.

## Library

- A scan no longer fails on an album whose artist and name already belong to an album
  indexed in another folder. A folder that moved takes over the existing album; a second
  copy that still holds audio is skipped and logged as
  `Skipping album folder …: album N is already indexed at …` until the copies are
  consolidated.
- Tracks whose file names carry no UUID no longer collide when the same recording
  appears on two releases, and a renamed file keeps its track.

## VirtualDJ

- `CRATE_VDJ_ENABLED` and `CRATE_VDJ_AUTOMATION_ENABLED` in `.env` now reach the API;
  before, setting them had no effect.
- The plugin itself ships separately as Crate for VirtualDJ 1.0.0 (`crate-vdj-v1.0.0`),
  and cratemusic.app presents it in the For DJs section.

## Upgrading

- Migration 143 adds the error inbox tables and migration 144 admits the
  `ops.errors.read` grant. Both run on upgrade. Downgrading past 144 fails while an
  integration holds that grant.
- Existing Crate Agent and Crate Operator integrations keep their grants: add
  `ops.errors.read` in Admin > Agents to let them read the inbox.

## Downloads

- **Server:** `curl -fsSL https://cratemusic.app/install.sh | bash` for new home installs,
  or `crate install --dir <install folder>` to upgrade one. Binaries for Linux and macOS
  on amd64 and arm64 are attached, with `crate-checksums.txt`.
- **Desktop:** `Crate-macos-arm64.app.zip`, `Crate-macos-intel.app.zip`,
  `crate-windows.exe`, `crate-windows.msi`, `crate-linux.AppImage`, `crate-linux.deb` and
  `crate-linux.rpm`. Each is also at
  `https://github.com/thecrateapp/crate/releases/latest/download/<file>`. macOS builds
  are ad-hoc signed.
- **Android:** `crate.apk` (signed and minified), plus the versioned APK and App Bundle.
