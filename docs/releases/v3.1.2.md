# Crate 3.1.2

Crate 3.1.2 measures playback quality and recommendation outcomes, exports the
application's metrics to Prometheus with recording rules and dashboards, and gives
Crate Operator the alert rules that will watch them. It also fixes the CPU readings on
the Stack map. It has no database migration.

Crate is published under the GNU Affero General Public License v3.0 (AGPL-3.0).

## Playback quality

- **Continuous telemetry from Listen.** Listen now reports each play request, whether
  it started, was cancelled or failed and why, and how long playback stayed active.
  Events are buffered in memory with an expiry and a rate limit, retried without being
  counted twice, and dropped on logout or when the server changes. Losses on the
  device are reported instead of hidden.
- **Playback health in System Health.** Start success, stall time, startup time and
  failed starts over the last 15 minutes. Below 20 play attempts the ratios are hidden,
  and older clients or lost events are named as caveats.
- **Per device, not per user.** The server limits telemetry per client session with a
  higher ceiling per user, so two devices of one listener do not throttle each other.

## Recommendations

- Radio batches record whether they were generated, replayed or recovered, how full
  they were and which relaxation step supplied each track. Music Paths plans record
  whether they completed, ran short or found nothing.
- Listen reports what happened when the queue ran out during radio or Infinite: more
  tracks arrived, the source was exhausted, or the listener stopped.
- An hourly task measures how often radio and path tracks are skipped in their first
  30 seconds.

## Prometheus and dashboards

- The API, workers, projector, readplane and media worker expose their metrics on an
  internal port that is never published on the host. Monitoring scrapes them over a
  dedicated internal network that only Prometheus and those services join.
- 29 recording rules cover request, stream, playback, worker and telemetry rates and
  percentiles, each with its sample size. Missing data stays missing; no rule turns it
  into zero. Grafana gains Overview, Playback, Workers and projector, and Telemetry
  health dashboards.
- A monitoring deploy now verifies only the monitoring services' own scrapes, so a
  restarting application container no longer rolls monitoring back.

## Crate Operator and MCP

- The Operator supervisor can read a fixed list of Prometheus queries with tight time
  and size limits and uses them for alert rules on monitoring health, queues and the
  projector, availability and playback. Every new rule ships disabled; rules are
  enabled one at a time after a shadow period.
- Three read-only MCP tools: `get_playback_quality`, `get_product_kpis` and
  `get_stack_status`, also available to Crate Agent.

## Stack map

- **CPU per service.** With monitoring enabled, the map showed memory for every
  service but no CPU. cAdvisor stamps its samples about once a minute, so a
  one-minute rate rarely had two samples to compare. CPU, host CPU and Edge request
  rates now use two-minute windows, which hold four scrapes of each source.
- `make observability-grafana` opens an SSH tunnel to Grafana and the browser.

## Upgrading

- Application metrics reach Prometheus once the monitoring deployment from this
  release has created the `app-metrics` network and the application is redeployed.
  Set `OBS_APP_METRICS_NETWORK` in the application `.env` when monitoring runs as its
  own project, as described in
  [Monitoring](https://docs.cratemusic.app/operations/monitoring).
