# Crate 3.5.0

Crate 3.5.0 makes federated search ask only the peers that may hold an answer, using
per-peer catalogue summaries, and applies the catalogue scope to owner search. Decks
syncs cues and corrections with the server, and Smart Mix plans Decks transitions with a
user's own corrections. On Android, Listen keeps its place and its play history when the
screen is off, rides out lost networks and caches streamed tracks. A security pass puts
Docker behind a filtering proxy, hardens sessions and the bootstrap admin, confines
library writes, and lets users export their data and delete their account. Admin's Stack
map shows scrapes, store load and each service's queries, and Launch fix can hand a bug
to the Crate Software Factory. The database goes from migration 165 to 169.

## Federation

- **Per-peer summaries.** An instance publishes, for each distinct search scope it grants
  its peers, a compact summary (a Bloom filter at a 1 % false-positive target) of the
  words and word prefixes of 3 or more characters in the artist names, album titles and
  track titles that scope may search. Peers with the same scope share one summary. The
  maintenance worker rebuilds stale summaries every 5 minutes and drops unused ones. No
  summary is built when search is denied, or when a role or user grant could let some
  users see more.
- **Fewer peers asked.** A federated search now asks only the peers whose summary may
  contain the query, plus the peers whose summary shows more albums of a found artist than
  your library has. A peer without a fresh summary is always asked, as is every peer for a
  query with no word of 3 or more characters. If the summary store fails, every peer is
  asked. When no summary matches, Listen shows no network section for that search.
- **Fetching and freshness.** Peers that advertise the new `catalog.summary` capability
  are polled every 15 minutes, and a summary is fetched again as soon as their delta feed
  announces a new one. A summary not confirmed for 30 minutes is ignored, and a refused or
  invalid one is deleted. `GET /api/federation/v1/catalog/summary` serves it, signed, with
  `304` on `If-None-Match`, and never builds it in the request. On a reference catalogue of
  1,050 artists, 10,900 albums and 138,000 tracks a summary is about 185 KB and takes
  3.5 s to build.
- **Owner search follows the catalogue scope.** Search answered for a peer now applies the
  same scope as the catalogue manifest: the grant's entity types and IDs, the catalogue
  filter's allow and deny lists, quarantined albums and hidden artists. Before, it applied
  none of these.
- **Known limits.** A match in the middle of a word is not routed (`head` does not find
  Radiohead through a summary), and some locale-specific case folding can differ from
  PostgreSQL. Peers paired before this release keep their stored capabilities, so the
  15-minute poll skips them until their delta feed refreshes them.

## Decks

- **Cue and correction sync.** Decks stores hot cues, loops, jumps and the main, intro and
  outro cues, plus BPM, beat-grid and key corrections, on the server for each user and
  track. `POST /api/decks/cues/query` and `POST /api/decks/corrections/query` read up to
  200 tracks in one request; `PUT /api/decks/cues/{entity_uid}` and
  `PUT /api/decks/corrections/{entity_uid}` write a whole set against a base revision and
  answer `409` with the current one on a conflict. Every response carries the server's
  clock. These routes take only a user session, never a `crv_` access token. The data
  survives library rescans.
- **Corrections in Smart Mix.** Plans that Decks asks for use the signed-in user's
  corrections instead of the shared track profile. A corrected BPM or grid moves the beat
  anchors and keeps the bar phase; phrases snap to the corrected downbeats when the BPM is
  within 2 % of the profile's and are dropped otherwise. A corrected key sets the Camelot
  key. Listen, Android's background continuation and VirtualDJ keep the shared profile,
  and plans are cached per correction, so users never share a plan unless their
  corrections are identical.
- **Now playing and plays.** `POST /api/me/now-playing` accepts the deck (1 to 4) and the
  mix session. Plays sent with `X-Crate-App: decks/<version>`, or from a Decks session,
  are recorded as Decks plays, and Decks heartbeats keep its session active.

## Listen on Android

These fixes ship in the native Android player and need the 3.5.0 Android app.

- **Resume where playback left off.** After several tracks with the screen off, pausing
  and later reopening the app started again from the track that was playing when the
  screen went off. Listen now resumes the queue at the native player's track, position
  and play or pause state.
- **Plays heard with the screen off are recorded.** The native player keeps a log of track
  changes and play checkpoints until Listen acknowledges them, and Listen replays it on
  start, so those plays reach your history. Replayed plays carry the time Listen counted
  them, not the time they played, and the seconds heard on a track before the screen went
  off are still lost.
- **Lost networks.** Playback stopped with "android_getaddrinfo failed: EAI_NODATA" during
  a Wi-Fi to mobile handover, in a tunnel or in Doze. The player now retries connection
  failures for about 190 s while it buffers, and if the stream still fails it prepares the
  same track and position again when the network returns, for up to 15 minutes. Listen
  shows one "Connection lost" notice saying playback will continue when the network is
  back. Pausing, replacing the queue or stopping ends the wait. HTTP errors still fail as
  before.
- **Stream cache.** Streamed tracks are cached on the device, up to 1 GB (least recently
  used first) in the app's cache directory, which Android may clear. The current and the
  next track are downloaded ahead, plus one more on an unmetered network, so playback
  continues through a lost connection, and a track still in the cache is not downloaded
  again.
  Tracks over 250 MB still stream. A transcoded variant is only cached once the server
  has it ready, and credentials are never part of the cache key. The audio is stored
  unencrypted in app-private storage, and there are no cache settings yet.

## Accounts and security

- **Your data.** Listen's Settings has a "Your data" section. A user can export their data
  as a ZIP built by a worker (profile, sessions, devices, playlists, Crates, likes,
  ratings, play history, Decks cues and corrections and more; never password hashes,
  token digests, file paths or other users' identities), downloadable only by them for
  24 hours. They can also delete their own account with their password, or with a sign-in
  on the same session in the last 10 minutes for accounts without one. The last remaining
  owner or admin cannot (`409`). Deletion revokes every session, access token and the
  OpenSubsonic key, and is the same soft delete Admin uses; shared playlists, Crates and
  Jam rooms stay for others.
- **Bootstrap admin.** A new install no longer has the password `admin`. Without a
  `DEFAULT_ADMIN_PASSWORD` of at least 8 characters that is not a common default, Crate
  generates one, never logs it, and writes it to `initial-admin-password` in `DATA_DIR`
  (owner-only). The bootstrap admin must choose a new password at first sign-in in Admin.
  Existing instances are not changed or flagged.
- **Sessions.** Session cookies now default to `SameSite=Lax`. State-changing requests
  authenticated by the session cookie or by trusted proxy headers are refused when they
  come from an origin outside the configured CORS origins. Bearer tokens, media tickets,
  access tokens, OpenSubsonic, federation and MCP credentials are unaffected. Tokens are
  no longer accepted in the query string by the API, Jam's WebSocket or the read plane.
- **OAuth.** OAuth state is signed with a key derived from the instance secret, and the
  PKCE verifier stays on the server (single use, 15 minutes). Outside development, OAuth
  sign-in requires Redis.
- **Docker access.** `crate-api` no longer mounts the Docker socket. It reaches Docker
  through `crate-docker-proxy`, a filtering HAProxy that allows listing, inspecting and
  logs, and restart, stop and start only on the containers Admin manages. Worker
  containers drop all Linux capabilities and cannot gain privileges.
- **Library writes.** Every worker filesystem change must resolve inside the library or
  another allowed root: no deleting a root, no path traversal and no escape through a
  symlink. Folders that link to another disk need `CRATE_LIBRARY_EXTRA_ROOTS` (see
  Upgrading). The unused album organizer, which wrote to the library from the API, is
  removed, and `crate-cli` no longer loops on symlink cycles.
- **Secrets from files.** Secrets such as `JWT_SECRET`, `CRATE_CREDENTIAL_KEY`, database
  and Redis URLs, API keys and `DEFAULT_ADMIN_PASSWORD` can be read from the file named by
  `<NAME>_FILE`, as Docker secrets provide. The file wins over the variable. The Compose
  defaults are unchanged.
- **Dependencies.** Python packages install from hashed lock files, and CI checks that
  the locks are current and audits them with `pip-audit`.

## Admin

- **Stack map resources.** Most services showed N/A for CPU and memory after containerd
  restarted, because the observability proxy kept a dead socket. The proxy now mounts the
  socket's directory, read-only, so it follows a recreated socket.
- **Worker pulses.** Task pulses reach the worker that ran them: task durations carry
  their queue, and `crate-worker` shows its `ai` and `ai_bulk` queues.
- **Monitoring and stores.** Each Prometheus scrape pulses from its service into the
  monitoring dome, failing targets pulse as errors, and Prometheus shows how many targets
  are up. PostgreSQL shows transactions per minute and each Redis commands per minute.
  These reads run every 30 s only while someone has the Stack page open.
- **Queries per service.** Every service counts its database statements
  (`crate_db_queries_total`, exported only to Prometheus, about 0.44 µs per statement),
  and each shows `Queries N/min` and pulses into PostgreSQL at that rate. The workers'
  missing links to PostgreSQL are drawn.
- **Status.** `/api/status` failed with a 500 when any album had a year that did not start
  with four digits, such as `11-0`, or a full date. Decades now count from the first four
  digits and skip the rest.

## Error Inbox

- **Launch fix through the factory.** Launch fix can hand a bug to the Crate Software
  Factory instead of the GitHub Actions workflow. The factory reproduces the bug with a
  failing test, fixes it and opens a draft `autofix` pull request; a person still accepts
  its spec before it starts and merges at the end. Choose it as the Fixer in the Launch
  fix settings, with the factory's address (plain HTTP only on a tailnet), its pull
  request author and a token stored as a secret.
- **Retries and expiry.** A submission whose answer was lost adopts the bug the factory
  created for that run and never submits it twice. A factory run with no pull request
  expires after 48 hours (GitHub Actions keeps 6 hours), and expiry also cancels a bug
  still waiting for spec acceptance.
- **Bug payloads.** First- and last-seen times are sent as ISO 8601 strings; datetimes
  broke the request.

## Enrichment

- **Spanish biographies.** When an artist's English Last.fm biography is empty, Crate uses
  the Spanish one if there is one, in normal enrichment, Admin's bio research and agent
  enrichment. A failed lookup keeps the rest of the profile.

## Upgrading

- **Migrations 166 to 169** run on start. All are additive:

  - 166 adds `user_track_cue_sets`, `user_track_cues` and `user_track_corrections` for
    Decks;
  - 167 adds `password_change_required` to `users` (default false);
  - 168 adds `user_data_exports` and `authenticated_at` to `sessions`, filled from each
    session's creation time;
  - 169 adds `federation_catalog_summaries` and `federation_peer_summaries`.

  Each has a downgrade that drops what it added. Downgrading 166 deletes every user's
  synced Decks cues and corrections, and 168 deletes the export history; 169 holds only
  derived data, which is rebuilt.

- **Docker proxy.** Deploy this release with `make deploy`, which ships
  `deploy/docker-proxy/haproxy.cfg`. Crate Operator's automatic path does not, and
  without that file `crate-docker-proxy` does not start and Admin's Stack page shows
  Docker as unavailable. Home installs get the file from the installer.
- **Bootstrap admin.** Only installs whose database has no users yet are affected. If you
  set `DEFAULT_ADMIN_PASSWORD`, use at least 8 characters that are not `admin`,
  `password`, `changeme` or `change-me`; otherwise read the generated one from
  `initial-admin-password` and delete the file after signing in. If an existing instance
  still uses `admin`, change it.
- **Cross-site setups.** Listen, Admin and the API are expected to share a registrable
  domain. If yours do not, set `CRATE_AUTH_COOKIE_SAMESITE=none` (it applies only over
  HTTPS), and make sure every web origin is in the CORS list, or state-changing requests
  from it are refused.
- **Tokens in URLs.** Clients that still send session tokens in the query string get
  `401` until updated. No first-party client has done so since September.
- **OAuth.** Keep `REDIS_URL` set on `crate-api` for OAuth sign-in, and restart any
  sign-in that was in progress during the deploy.
- **Library on several disks.** If artist or album folders are symlinks into another
  disk, deleting, moving, merging, repairing or migrating them is now refused until that
  disk's container path is in `CRATE_LIBRARY_EXTRA_ROOTS`, mounted at the same path in
  `crate-api` and the read-write workers through a compose override. One invalid entry
  blocks every library change until it is fixed.
- **Observability.** The containerd fix reaches production with the next observability
  deploy, which recreates the proxy. Make, `observability-up.sh`, the remote deploy and
  the installer derive `OBS_CONTAINERD_SOCKET_DIR` from the socket they find.
- **Federation.** Nothing to configure. Peers on older releases have no summary and are
  still always asked.
- **Factory executor.** It cannot be selected until its address, pull request author and
  token are set, and the factory must allow the Crate host's address. GitHub Actions
  stays the default.
- **Last.fm.** The artist info cache key changes, so artist info cached before the upgrade
  is fetched again on next use.
- **Android.** The resume, play history, lost-network and stream cache fixes need the
  3.5.0 Android app. Older apps keep their current behaviour.
- **New and changed settings**, all optional:

  | Variable                             | Default                                         | Where                                  |
  | ------------------------------------ | ----------------------------------------------- | -------------------------------------- |
  | `CRATE_LIBRARY_EXTRA_ROOTS`          | empty                                           | `crate-api` and read-write workers     |
  | `CRATE_ACCOUNT_EXPORT_TTL_SECONDS`   | `86400`                                         | workers                                |
  | `CRATE_AUTH_COOKIE_SAMESITE`         | `lax` (was `none` over HTTPS)                   | `crate-api`                            |
  | `DEFAULT_ADMIN_PASSWORD`             | empty: generated (was `admin`)                  | first start only                       |
  | `CRATE_DEV_ADMIN_SEED`               | off; on in `docker-compose.dev.yaml`            | development only                       |
  | `<NAME>_FILE` for the listed secrets | unset                                           | Python services                        |
  | `OBS_CONTAINERD_SOCKET_DIR`          | `/run/containerd`, derived from the socket path | observability stack (`monitoring.env`) |
