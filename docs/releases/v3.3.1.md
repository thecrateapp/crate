# Crate 3.3.1

Crate 3.3.1 fixes federation pairing, Listen permissions and a timeout in Admin's
Global Catalog status panel. It does not add database migrations.

Crate is published under the GNU Affero General Public License v3.0 (AGPL-3.0).

## Federation pairing

- **Approval.** Admin uses the pairing request ID instead of the peer's node ID.
  It distinguishes incoming requests from offers awaiting approval at the other
  instance, and shows when a new request is needed after expiry.
- **Retry interrupted approval.** A valid, already signed acceptance can be retried
  after a failed callback. The same signed message is reused; its deadline is not
  extended. Cloudflare browser challenges produce a useful error in Admin.
- **Preserve owner decisions.** Trust, grants and pairing completion are committed
  together after signature verification. Retrying a completed exchange does not
  overwrite later permission changes. A pending exchange cannot restore a grant
  changed after consent.
- **Accurate expiry.** Pairing deadlines respect the validity of the signed node
  descriptors and parent messages, including older incoming offers.

## Listen permissions

- **Standard Listen grants work.** The permission validator now accepts
  `data_saver`, which Listen and Trusted Library already include in their delivery
  profiles. Earlier builds could reject the entire grant with
  `invalid_constraints`, blocking catalogue access and playback.
- **Access limits remain.** Unknown delivery profiles are rejected, and the Listen
  preset continues to exclude original audio.

## Global Catalog

- **Status panel.** Active genre-assertion counters filter out invalidated history
  before aggregation, allowing PostgreSQL to use the existing partial index. This
  prevents a full historical scan from timing out the Admin status request while
  preserving exact counts.

## Upgrading

- Upgrade both federation peers to receive the permission-validation fix on both
  sides. Mutual Listen requires each owner to grant Listen independently; an empty
  library on one peer is valid.
- If a grant was temporarily restricted to `delivery=["balanced"]` to work around
  the older validator, reapply the standard Listen preset after upgrading that
  instance to restore Data Saver delivery.
- A pairing request that has expired still requires a new offer. A valid request
  interrupted by a transport failure can be retried without changing keys.
- No database migration is required for this patch release.
