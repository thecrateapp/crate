# Crate 3.0.0

Crate 3.0 gives Listen and Admin a new interface, replaces the shell installer with the `crate`
installer, and moves Telegram to Crate Agent and Crate Operator. Upgrading from 2.7.x removes the
built-in Telegram bot and renames the agent pilot; read the
[upgrade guide](https://github.com/thecrateapp/crate/blob/v3.0.0/docs/technical/upgrade-v2-to-v3.md)
before you deploy.

## Highlights

- **A new interface for Listen and Admin.** One Crate v3 identity replaces the selectable visual
  themes. Both apps share one set of controls, dialogs, loading, empty and error states, and a
  skip link. Admin drops decorative icons, colours severity and log levels, and simplifies the
  Dashboard and Library Health.
- **Listening stats.** Listen gains a stats explorer with range summaries, a listening heatmap,
  movement, highlights and replay, previous-period deltas and new-entry badges. Crate Pulse, the
  instance-wide view, reads new daily rollups and hides its heatmap below three listeners.
- **Admin Insights.** Insights has Listening, Collection and Sonic explorer tabs. Collection
  compares what the library holds with what people play; the sonic explorer maps tempo, energy
  and loudness regions with nearby tracks.
- **Genre taxonomy facets.** Genres can carry reusable facets (era, instrumentation, language,
  mood, origin, rhythm, scene, sound, vocals), and raw tags can be classified as genre, facet,
  hybrid or ignored.
- **The `crate` installer.** `curl -fsSL https://cratemusic.app/install.sh | bash` downloads a
  checksummed Go binary and runs a step-by-step wizard:
  - `crate install` checks Docker, memory, disk and ports, asks for the access mode (`ports`,
    `hosts`, `dnsmasq` or `cloudflare`) and checks every integration key against its provider.
  - `crate configure [integration]` changes integrations later and restarts only what uses them.
  - `crate doctor [--json]` checks the machine, Docker, services, API and every configured key.
  - `crate mcp` lets an AI agent such as Claude Code or Codex drive the install. Secrets are
    typed into a local one-time page and never reach the agent.
  - A release installer pins `CRATE_IMAGE_TAG` to its own version, so installer v3.0.0 runs the
    v3.0.0 images.
- **Crate Agent and Crate Operator on Telegram** (opt-in). Crate Agent is a read-only assistant
  over the Crate MCP server: health, jobs, logs and schedules. Crate Operator can also make
  changes, but only after a bound admin approves each plan with Telegram buttons, and only while
  the provenance service confirms the stack runs official images. Both run on any instance:
  `crate configure agent` on installer setups, `make agent-init` on a checkout. They need
  `CRATE_MCP_ENABLED=true`, and Crate Operator also needs `CRATE_MCP_ACTIONS_ENABLED=true`.
  The operator supervisor sends health, failed-task and new-release alerts to the chat.
- **MCP server** (opt-in, since 2.7). `CRATE_MCP_ENABLED` still defaults to `false`. New
  credential presets "Crate Agent (read only)" and "Crate Operator" grant exactly what each
  assistant needs.
- **Smart Mix on Android** (opt-in, since 2.7). Planned transitions, beatmatch and bass swap
  now show in the fullscreen player when the native mixer runs them. Playlist rules can require
  Smart Mix profiles. Every flag defaults to off: `CRATE_SMART_MIX_ENABLED`,
  `CRATE_ANDROID_NATIVE_CROSSFADE_ENABLED`, `CRATE_ANDROID_BEATMATCH_ENABLED` and
  `CRATE_ANDROID_BASS_HANDOFF_ENABLED`, each depending on the one before it. `crate-api` reads
  them, and the shipped compose files do not pass them through, so set them in a compose
  override for `crate-api`.
- **amd64 and arm64 images.** Every image, including `crate-agent`, is published for both
  architectures, so Apple Silicon, Raspberry Pi 4/5 and ARM servers run native images. Release
  tags also tag every image with the version (`v3.0.0`).

## Fixes worth knowing

- Scrobbles follow Last.fm's rule: a track longer than 30 s counts once played for half its
  length or 4 minutes. Before, Android plays almost never reached Last.fm. Each provider's answer
  is now stored, and an invalid Last.fm session asks the user to reconnect.
- Android closes every native play and counts the time the native player observed. Listen keeps
  play events until the server stores them.
- Interrupted imports return to the pending queue. Setlists refresh only when outdated, from a
  worker task.
- Collection insights warm only the 30-day window, at most hourly. Library totals are cached, and
  hidden tabs pause polling.

## Breaking changes

- **The built-in Telegram bot is removed.** Migration 138 deletes its settings
  (`telegram_enabled`, `telegram_bot_token`, `telegram_chat_id`), including the stored token.
  Crate no longer reads `TELEGRAM_BOT_TOKEN` or `TELEGRAM_CHAT_ID`. Use Crate Agent or Crate
  Operator with a new bot, and revoke the old token in BotFather. Worker `--no-telegram` is
  accepted as a no-op for this release.
- **The web setup wizard is retired.** The Admin setup page and the `/api/setup` routes are gone.
  First-run setup belongs to `crate install`.
- **The agent pilot is renamed Crate Agent.** Service and container `crate-hermes-agent` (profile
  `hermes`) become `crate-agent` (profile `agent`), and the image is now
  `ghcr.io/thecrateapp/crate-agent`. State moves from `${DATA_DIR}/hermes-agent` to
  `${DATA_DIR}/crate-agent`. `CRATE_HERMES_MCP_URL` and `CRATE_HERMES_MCP_HOST` become
  `CRATE_AGENT_MCP_URL` and `CRATE_AGENT_MCP_HOST`. Drop `CRATE_HERMES_IMAGE`: it pointed at the
  upstream engine image.
- **The Crate Operator pilot changes shape.** The container `crate-hermes-operator` becomes
  `crate-operator`. The deploy overlay `.deploy/hermes.compose.yaml` is no longer read
  (`.deploy/crate-operator.compose.yaml` or `deploy/operator/compose.operator.yaml` replace it),
  and provenance runs as containers instead of the host `crate-provenance.service`.
- **The agent containers default to UTC.** With `TZ` unset, the agent used `Europe/Madrid`;
  `crate-agent` and `crate-operator` now use `UTC`. Set `TZ` in `.env`.
- **Removed from `.env.example`:** `LISTEN_APPEARANCE_SETTINGS_ENABLED` (build flag for the retired
  themes), plus `TIDARR_PASSWORD` and `NATIVE_OAUTH_LEGACY_REDIRECT_ENABLED`, which nothing read.
  Delete them from your `.env`.
- **iOS needs 16.4 or later.** iOS 15 devices stay on the last 2.x build.

## Database migrations

Crate applies migrations on startup. From 2.7.4 (revision 134) the upgrade runs:

| Revision | Change                                                                                                                                                         |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 135      | Instance listening rollups (`instance_track_daily`, `instance_entity_firsts`); builds `idx_user_track_daily_day` and `idx_user_entity_firsts_key` concurrently |
| 136      | Genre taxonomy facets and raw tag classifications                                                                                                              |
| 137      | `provider_results` on `user_scrobble_dispatches`                                                                                                               |
| 138      | Deletes the built-in Telegram bot settings                                                                                                                     |

Instances on 2.7.0 to 2.7.3 first apply the revisions they miss, up to 134. After the upgrade, `crate-api` queues one
backfill of the instance rollups, and stats dashboards rebuild under new `v3` keys. Take a
PostgreSQL backup first: a downgrade after these migrations means restoring it.

## Downloads

- **Server:** `curl -fsSL https://cratemusic.app/install.sh | bash` for new home installs, or
  `crate install --dir <install folder>` to upgrade one. Binaries for Linux and macOS on amd64
  and arm64 are attached, with `crate-checksums.txt`.
- **Desktop:** `Crate-macos-arm64.app.zip`, `Crate-macos-intel.app.zip`, `crate-windows.exe`,
  `crate-windows.msi`, `crate-linux.AppImage`, `crate-linux.deb` and `crate-linux.rpm`. Each is
  also at `https://github.com/thecrateapp/crate/releases/latest/download/<file>`. macOS builds
  are ad-hoc signed.
- **Android:** `crate.apk` (signed and minified), plus the versioned APK and App Bundle. Allow
  "Install unknown apps" for your browser or file manager. On first launch, enter your server's
  API URL (for example `https://api.example.com`) and sign in.
