# Crate 3.4.0

Crate 3.4.0 adds database backups managed from Admin, with off-site copies,
verification, restore drills and a recovery kit. Smart Mix gets analyzer v10, which
stops hearing fast four-beat tracks in three, and Listen can now plan with the v3
planner. Decks, the desktop DJ app, gets its library, batch profile and planner
routes. Listen searches paired peers on demand, the Linux desktop app integrates with
Ryoku, and pause and resume no longer go silent for a moment. Worker recycling, the
resource governor and the API's SSE connections are fixed. The database goes from
migration 160 to 165.

## Backups managed from Admin

- **Backups page.** Admin has a new **Backups** page under System, for owners and
  admins (capability `system.backups.manage`). It has Overview, Destinations,
  Policies and Runs, a Cmd+K entry and a sidebar counter of failing destinations.
  It backs up the PostgreSQL database only: music files, `.env` and its secrets
  need their own copies.
- **Destinations.** A folder of the backup directory, any S3-compatible bucket
  (presets for Cloudflare R2, Wasabi, MinIO, Hetzner Object Storage and AWS S3),
  Backblaze B2, SFTP, Google Drive and Dropbox, each a restic repository. Settings
  can be tested before saving without storing any secret. A new destination stays
  disabled until its first test passes. Secrets are write-only, encrypted with
  `CRATE_CREDENTIAL_KEY`, and never shown again. For SFTP, Crate generates the SSH
  key and pins the host key on the first test. Google Drive (scope `drive.file`) and
  Dropbox connect through OAuth with the install's own client, never rclone's
  shared one.
- **Policies.** Daily at a time, every N hours, or manual, with an optional window.
  Each destination receives the daily, weekly or monthly copies you choose, with
  its own retention. Policies also set the compression and how often to verify
  (`restic check` on a share of the data) and to run a restore drill. A drill
  restores the newest copy into a throwaway database on the same server, checks it
  and drops it. It refuses to touch the production database. Local dumps keep their
  own counts (3 days, 4 ISO weeks and 3 months by default).
- **Runs.** Every dump, retention, copy, verification and drill is recorded, with
  filters and paging. A failed run expands to its error and its task.
- **Recovery kit.** One file, encrypted with age and a passphrase of at least 12
  characters, with the repository and password of every destination, the SFTP
  private key and restore steps. Downloading it requires your account password.
  Admin warns until you confirm "I stored it".
- **Alerts and metrics.** Failing and late destinations, and failed dumps or
  retention, become alerts on the Overview and in the Crate MCP's observability
  summary, one per condition until it clears. Crate Operator's example supervisor
  config has a digest for them, shipped disabled. New gauges
  (`crate_backup_last_success_timestamp_seconds`,
  `crate_backup_run_duration_seconds`, `crate_backup_bytes`) feed Backup age, size
  and run-duration panels on Grafana's Workers and projector dashboard.
- **Import and before-upgrade copies.**
  `python -m crate.backups.cli import-destination` registers an existing restic
  repository with its password, never re-initialising it. A manual policy marked
  "Before upgrades" runs before `make deploy` migrates (see Upgrading).
- **Fixes from turning it on.** The connection test no longer asks an S3 key scoped
  to its bucket to create the bucket. A restore drill takes both of its locks on
  one database connection, so it no longer times out in workers with a pool of one
  plus one.
- **PostgreSQL backup sidecar.** On `docker-compose.yaml` deployments,
  `crate-postgres-backup` reads its retention and `pg_dump` options from `.env`, and
  `POSTGRES_BACKUP_DIR` can point it at the `crate_postgres_backups` volume. A new
  optional `crate-backup-offsite` service (profile `offsite-backup`, off by default)
  copies the weekly and monthly dumps to Cloudflare R2 and Google Drive with restic,
  and runs a monthly check and restore drill. See
  `docs/operators/postgres-offsite-backups.md`.

## Smart Mix

- **Analyzer v10.** Beat This! heard fast four-beat punk and metal in three, so such
  tracks got no downbeats and no phrases. When it now prefers three, madmom's
  downbeat network decides, and bars of three stay only if it hears three too. In
  the evaluation sets, 8 of the 10 tracks heard in three took four-beat bars and
  gained phrases. A 600 s track in three peaks at about 0.8 to 1.0 GB, Beat This!'s
  own peak.
  madmom's networks are CC BY-NC-SA 4.0. The attribution is in
  `docs/technical/smart-mix-operations.md`.
- **Model beats are kept.** A library reanalysis no longer replaces a profile that
  has Beat This!'s beats with one from Crate's own tracker. A changed file still
  takes any new analysis.
- **The backfill keeps up.** A completed campaign reopens by itself when new
  profiles need the model (checked every 10 minutes). Admin shows **Pause
  reopening** while it is completed. Profiles from Crate's own tracker are upgraded
  to Beat This! on tracks up to 600 s, where the analysis worker can run the model;
  elsewhere coverage counts them as current.
- **Faster backfill.** Analysis processes take a new message only when they are
  free, and a waiting coordinator checks again within 10 s instead of 30 s, so the
  backfill slots stay busy instead of idling about half the time.
- **The backfill no longer stops on a failed refresh.** A failure to refresh
  Admin's coverage numbers is logged and the next pass is still queued. Before, one
  failed coverage query stopped the campaign for good.
- **Listen on the v3 planner.** With `CRATE_LISTEN_SMART_MIX_V3_ENABLED=true`, the
  server recommends `smart-mix-v3` to Listen, and Listen from this release plans
  with it, including Android's background continuation. In Listen, v3 skips at most
  10 s of intro and cuts at most 20 s of outro, and never plans a mix longer than
  the user's maximum transition. VirtualDJ and older apps stay on v2.

## Decks

- **Library.** `GET /api/decks/containers` lists playlists, crates, genres, moods,
  recent and likes. `GET /api/decks/containers/{kind}/{id}/tracks` pages their
  tracks, up to 500 at a time, with BPM, key, energy and playability, and answers
  `If-None-Match` with `304`.
- **Batch profiles.** `POST /api/decks/mix-profiles` returns the full Smart Mix
  profiles of up to 200 tracks in one request and one SQL statement, and lists the
  tracks that have none.
- **DJ search.** DJ search results carry the same `format`, `bitrate`,
  `sample_rate`, `source_revision` and `profile_quality` fields as the library
  pages, so Decks can import search results directly.
- **Planner context.** Decks has its own beatmatch and bass handoff switches,
  `CRATE_DECKS_BEATMATCH_ENABLED` and `CRATE_DECKS_BASS_HANDOFF_ENABLED`, on by
  default. Decks' assist mode allows long blends of up to 96 s. Every Decks plan
  carries the limits it was planned with. Plans for every other client are
  unchanged.
- **Help pages.** docs.cratemusic.app has a Decks section with the app's user help,
  where its in-app help links lead. The app is now called Decks rather than Crate
  Decks.

## Federated search in Listen

- **Results from the network.** When a search finds fewer than 5 local results,
  Listen also asks your paired peers; otherwise it asks only the peers whose
  catalogue copy here is out of date. Their answers appear under "More results
  from the network", grouped by artist, album or track with the peers that hold
  them. Local results show at once and remote ones stream in.
- **Bounded waits.** Each peer gets 1.5 s and the whole search 2 s. The header
  shows how many peers answered. When some did not, "Search the network again"
  picks up their late answers from the server's cache. An empty result says how
  many peers were searched, never that the music is not in the network.
- **Only on purpose.** Listen asks the network for a submitted query, or after
  300 ms without typing, and never for queries under 3 characters. The top bar
  dropdown stays local.
- **Peer limits.** An instance answers at most 120 searches a minute from each peer
  and 30 from each remote user, then `429` with `Retry-After`. Only approved,
  enabled peers that offer catalogue search are asked. Answers carry only remote
  identities and whitelisted fields, including from peers on older releases.
- **Not yet.** Remote artists and albums are listed but do not open a page. Remote
  tracks play.

## Listen playback

- **Resume is heard at once.** Pause and resume fades now run on the audio clock.
  Before, a resumed track could play silently for about two seconds while the
  playhead moved, because its fade-in waited for the page. A play during a fade-out
  restores the volume.
- **Fewer re-renders.** Player actions no longer change on every progress update,
  which made every card, row and button on the page re-render about four times a
  second during playback.

## Linux desktop and Ryoku

- **Ryoku integration.** The Linux desktop app works with Ryoku (Hyprland or niri)
  and other tiling compositors. On those it drops its titlebar and never moves or
  resizes its window. Its Wayland app ID is `app.cratemusic.crate.desktop`.
- **Launcher and MCP.** `crate-desktop --launcher` lists Crate's music in Ryoku's
  launcher, with cover art, and plays what you pick. `crate-desktop --mcp` is a
  stdio MCP server for now playing, transport, EQ, search and play. Both talk to the
  running app through a control socket in `$XDG_RUNTIME_DIR/crate/` and never start
  it.
- **Desktop behaviour.** One notification per new track, only while playing and not
  focused, with "Show Crate" and "Next". An idle inhibitor is held while playing; a
  manual suspend and the lid still work. MPRIS gains seek, volume, shuffle and loop.
  Crate shows as one dock icon.
- **Lighter on WebKitGTK.** Main-thread CPU goes from 13 to 15 % to about zero when
  idle, and from about 40 % to 8 % while playing.
- **Arch package.** Releases attach `crate-desktop-bin`, an Arch package of the
  `.deb`, installable with `sudo pacman -U <asset URL>`. It is not on the AUR yet.

## Reliability

- **Analysis worker restarts.** A worker process recycled itself when its lifetime
  peak memory passed 1,500 MB, which stopped every analysis process and restarted
  the container. It now checks current memory, returns what it can, and if still
  over the limit finishes its task and retires alone. The limit is configurable.
- **Resource governor.** Short iowait bursts on idle disks no longer defer governed
  work for 5 minutes. iowait counts only when the kernel's 10-second IO pressure
  average is at least 10 %, or when the kernel reports no IO pressure. A deferred
  Smart Mix coordinator checks again within 30 s.
- **SSE connections.** Event streams of finished tasks leaked a Redis connection
  each until the pool was full. Admin's Stack page then showed no CPU or memory and
  snapshot streams fell back to slow polling. Every path now closes its
  subscription, Admin opens no stream for a task it knows is finished, and Jam
  falls back to local mode when the pool is full.
- **Fast worker health.** `crate-fast-worker` no longer reports `unhealthy` while
  working: its readiness probe is much cheaper and the health check timeout goes
  from 7 s to 15 s.
- **PostgreSQL shared memory.** `crate-postgres` gets 1 GB of `/dev/shm` in the
  project compose, so parallel queries no longer fail with "No space left on
  device".

## Deploy and build

- **Agent containers.** `crate-agent` and `crate-operator` are no longer recreated
  on every release, only when their image or configuration changes. The deployed
  release is read from the deployment marker, and the agent keeps five contexts
  instead of all of them.
- **Image builds.** Image builds are scoped to the workflow jobs and sources that
  changed.
- **Beat This! checkpoint.** The analysis worker image downloads the checkpoint
  from either JKU share endpoint, still checked against its pinned SHA-256. Image
  builds had failed since one endpoint started answering errors.
- **Rollback.** Rolling back a failed release that added a service restores the
  previous compose file and removes the added service.
- **Project.** A showcase site for Crate for Ryoku (`crate-ryoku-site`, in the
  project compose), marketing voice and content checks, and test and docs fixes.

## Upgrading

- **Migrations 161 to 165** run on start. All are additive:

  - 161 adds `meter_margin` and `meter_arbiter` to `track_mix_signals` (two nullable
    columns);
  - 162 adds `backup_runs`;
  - 163 adds `backup_destinations`;
  - 164 adds `backup_policies` and `backup_policy_destinations`, and links
    `backup_runs` to them;
  - 165 adds the cached snapshot listing to `backup_destinations`.

  Each has a downgrade that drops what it added, including any backup history and
  destinations.

- **Smart Mix v10.** Start the v10 campaign from Admin as "Running the v10
  backfill" in `docs/technical/smart-mix-operations.md` describes. Signals with
  four-beat bars only rerun `crate-cli`; the ones with bars of three rerun Beat
  This! and the arbiter. A campaign that stopped on a failed coverage refresh has to
  be started again from Admin.
- **Listen on v3.** Nothing changes until you set
  `CRATE_LISTEN_SMART_MIX_V3_ENABLED=true` and recreate `crate-api`. Listen picks it
  up at its next start. To roll back, set it to `false` and recreate `crate-api`.
- **Decks.** Decks gets beatmatch and bass handoff wherever Smart Mix is on. Set
  either switch to `false` to keep it off.
- **Backups engine.** Home installs run it by default: a nightly dump inside the
  maintenance window into `${DATA_DIR}/crate/backups`, kept 3 days, 4 weeks and
  3 months. `docker-compose.yaml` keeps
  it off (`CRATE_LOCAL_BACKUPS_ENABLED=false`) while `crate-postgres-backup` makes
  the dumps. The move is described in `docs/technical/admin-backups.md`. Before
  connecting Google Drive or Dropbox, register
  `https://admin.<DOMAIN>/api/admin/backups/oauth/callback` in your own OAuth client.
  Keep `CRATE_CREDENTIAL_KEY` safe: without it the stored secrets cannot be read.
  Keep the recovery kit too, which does not depend on it. A Google Drive repository
  written by the off-site sidecar with rclone's shared client cannot be imported;
  connect Google Drive for a new one.
- **Before-upgrade backups.** `make deploy` now runs the "Before upgrades" policies
  in `crate-maintenance-worker` before anything changes, and stops if they fail. It
  does nothing while the engine is off.
- **PostgreSQL backup sidecar** (`docker-compose.yaml` only). Its defaults are now
  3 daily, 4 weekly and 3 monthly dumps at `-Z6`, instead of 7, 4 and 6 at `-Z1`.
  Set the `POSTGRES_BACKUP_KEEP_*` variables to keep more. To move the dumps into
  the `crate_postgres_backups` volume, follow the ops runbook. The workers also
  mount `POSTGRES_BACKUP_DIR` at `/backups`, unused until `CRATE_BACKUP_DIR=/backups`.
- **Analysis worker memory.** Each worker process now runs as its own pool, which
  adds about 230 MB to `crate-analysis-worker` with 8 processes and about 64 MB to
  `crate-worker` with 3. With high night concurrency, consider raising
  `ANALYSIS_WORKER_MAX_RSS_MB` within the container's memory limit.
- **Agent and operator containers.** The first deploy of this release recreates
  them once. After that, unrelated releases leave them running. The first activation
  prunes agent contexts beyond the five most recent, so a rollback further back than
  five deploys cannot use a cached context. A deploy creates
  `${DATA_DIR}/crate-agent/context` when it is missing. If Docker already created it
  owned by root, fix its ownership once. Rolling back to an earlier release keeps
  working, and a leftover `CRATE_RELEASE_SHA` in a home `.env` is harmless.
- **Governor.** If you raised `CRATE_RESOURCE_MAX_IOWAIT_PERCENT` or lowered
  `CRATE_RESOURCE_DEFER_SECONDS` to work around deferred backfills, you can return
  them to their defaults.
- **New settings**, all optional:

  | Variable                                                                                       | Default                                        | Where                                           |
  | ---------------------------------------------------------------------------------------------- | ---------------------------------------------- | ----------------------------------------------- |
  | `CRATE_LISTEN_SMART_MIX_V3_ENABLED`                                                            | `false`                                        | `crate-api`                                     |
  | `CRATE_DECKS_BEATMATCH_ENABLED`                                                                | `true`                                         | `crate-api`                                     |
  | `CRATE_DECKS_BASS_HANDOFF_ENABLED`                                                             | `true`                                         | `crate-api`                                     |
  | `CRATE_LOCAL_BACKUPS_ENABLED`                                                                  | on; `false` in `docker-compose.yaml`           | workers                                         |

  | `POSTGRES_BACKUP_KEEP_DAYS` / `_WEEKS` / `_MONTHS`                                             | 3 / 4 / 3                                      | `crate-postgres-backup`                         |
  | `POSTGRES_BACKUP_EXTRA_OPTS`                                                                   | `-Z6`                                          | `crate-postgres-backup`                         |
  | `RESTIC_PASSWORD`, `CRATE_OFFSITE_R2_*`, `RCLONE_CONFIG_GDRIVE_*`, `CRATE_OFFSITE_GDRIVE_PATH` | empty; path `crate-backups`                    | `crate-backup-offsite`                          |

## Downloads

- **Server:** `curl -fsSL https://cratemusic.app/install.sh | bash` for new home installs,
  or `crate install --dir <install folder>` to upgrade one. Binaries for Linux and macOS
  on amd64 and arm64 are attached, with `crate-checksums.txt`.
- **Desktop:** `Crate-macos-arm64.app.zip`, `Crate-macos-intel.app.zip`,
  `crate-windows.exe`, `crate-windows.msi`, `crate-linux.AppImage`, `crate-linux.deb` and
  `crate-linux.rpm`. Each is also at
  `https://github.com/thecrateapp/crate/releases/latest/download/<file>`. macOS builds
  are ad-hoc signed.
- **Android:** `crate.apk` (signed and minified), plus the versioned APK and App Bundle.
