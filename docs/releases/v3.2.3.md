# Crate 3.2.3

Crate 3.2.3 moves every call to an AI model off the HTTP requests and the general worker
queues into two lanes of its own, and brings the Windows desktop packages back after 3.2.2
shipped without them. It has no database migration.

Crate is published under the GNU Affero General Public License v3.0 (AGPL-3.0).

## AI work in its own queues

- **Two lanes for AI work.** `ai` runs interactive work with a limit of 300 s per task:
  catalog refresh, profile tests, show extraction, artist bio research, translation drafts
  and the new proposal tasks below. `ai_bulk` runs the long genre taxonomy batches. A slow
  provider no longer holds the `default`, `fast` or `maintenance` queues, and a taxonomy
  batch no longer delays interactive work.
- **No HTTP request waits for a model.** Generating a genre EQ, proposing a taxonomy node,
  writing a system playlist description with AI and analyzing an artist hero candidate now
  answer at once with a task, and Admin fills in the result when it is ready. Asking twice
  joins the task already running, and a late draft never overwrites a newer one.
- **Music Paths** in Listen appear at once with the deterministic path and an
  `AI · Refining` label, then refresh to the refined revision when the worker finishes it.
- **Waiting for provider capacity.** When a provider connection is at its
  `max_concurrent`, an interactive task waits and retries (5–30 s, up to ten times, only
  before its first paid call) instead of failing. A taxonomy batch waits inside its own
  budget, gives way to pending interactive work and leaves one slot free.
- **Every provider call ends before its task's time limit**, and a worker killed in the
  middle of a call releases its provider slot.
- **Admin Tasks and the dashboard** show the `ai` and `ai_bulk` lanes with running and
  pending tasks and the age of the oldest pending one, and draw a task waiting for capacity
  as deferred. The `ai.capacity.requeue` and `ai.capacity.wait` metrics count those waits.
- [Smart Mix operations](https://docs.cratemusic.app/operations/smart-mix-operations)
  explains how to size the lanes, and [AI agents](https://docs.cratemusic.app/operations/ai-agents)
  where model calls run.

## Desktop

- **Windows is back.** 3.2.2 published no `crate-windows.exe` or `crate-windows.msi`: the
  build stopped when Sentry rejected debug files of build tools that never ship. The build
  now uploads only the app's own debug symbols, and a Sentry failure no longer keeps the
  packages out of the release.

## Upgrading

- No migration: the database stays at 144.
- `crate-worker` now consumes `ai` and `ai_bulk` next to its usual queues. The release
  Compose files already do it; if your `.env` or an overlay replaces the `crate-worker`
  command, add `ai,ai_bulk` to its queues, or AI actions will stay pending.
- `crate-worker` gets a higher memory limit (2304 MiB, up from 1536 MiB) and waits up to two
  minutes on stop so that AI calls in flight can finish.
- Two optional variables size the lanes: `CRATE_AI_WORKER_THREADS` (2 by default) and
  `CRATE_AI_BULK_WORKER_THREADS` (1). Keep the first at or below the `max_concurrent` of the
  connection that serves the interactive actions.

## Downloads

- **Server:** `curl -fsSL https://cratemusic.app/install.sh | bash` for new home installs,
  or `crate install --dir <install folder>` to upgrade one. Binaries for Linux and macOS
  on amd64 and arm64 are attached, with `crate-checksums.txt`.
- **Desktop:** `Crate-macos-arm64.app.zip`, `Crate-macos-intel.app.zip`,
  `crate-windows.exe`, `crate-windows.msi`, `crate-linux.AppImage`, `crate-linux.deb` and
  `crate-linux.rpm`. Each is also at
  `https://github.com/thecrateapp/crate/releases/latest/download/<file>`. macOS builds
  are ad-hoc signed.
- **Android:** `crate.apk` (signed and minified), plus the versioned APK and App Bundle.
