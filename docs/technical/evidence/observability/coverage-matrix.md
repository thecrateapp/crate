## Cross-cutting errors, logs and alert delivery

- **Sentry runtime coverage in code:** Python `app/crate/observability/sentry.py:95–135`, Go `app/readplane/internal/observability/sentry.go`, Rust media-worker `app/media-worker/src/observability.rs:67–119`, Listen web `app/listen/src/lib/sentry.ts:12–31`, Capacitor `sentry-capacitor.ts:9–26`, Tauri `app/listen-desktop/src-tauri/src/observability.rs:45–93`, Cast `app/cast-receiver/src/sentry.ts:118–135`; Admin/Docs use shared redaction module `app/shared/web/sentry.ts`. DSN absence disables collection. Releases/environment, sampling and PII redaction exist; project configuration and actual ingestion are unverified. CI wiring for native/web DSNs and releases exists in `.github/workflows/build-{android,ios,desktop,images}.yml`. Do not confuse CI upload wiring with verified symbolication of a production event.
- **Tracing vs request correlation:** `app/crate/api/trace_middleware.py:69–127` validates/generates `X-Trace-ID`, returns it and injects it into logs; readplane access logs also carry it. This is correlation scaffolding, not proof of a complete distributed span tree. Python task scope starts a queue transaction (`observability/sentry.py:119–135`); media-worker starts its own HTTP transaction (`http.rs:49–59`). Python media HTTP client adds no explicit propagation headers (`media_worker.py:141–155`). Web tracing integration exists, but no explicit tracePropagationTargets setting in the inspected init. Validate inbound/outbound/CORS/queue handoffs and sampling, not a blanket claim that there is no tracing.
- **Logs/retention:** root/home compose use Docker local20MiB×5 rotation (`docker-compose.yaml:5–9`, `docker-compose.home.yaml:7–11`); this is bounded disk, not a guaranteed number of days. Python worker stdout is plain text (`worker.py:65–68`); readplane is JSON. Explicit worker logs are PG7days (`db/worker_logs.py:26–53,111–124`), tasks7days and task events48h (`worker.py:213–232`), cleanup every3600s (`535–541`). Local outbox delivered retention7days is separate (`db/domain_event_outbox.py:198–225`). Logs in PG cannot diagnose a PG outage on their own. No Loki/central log ingestion in PR0.
- **Supervisor already exists:** `deploy/operator/supervisor.py:19,61–79` has availability/high/low/drift/progress/stuck/digest, freshness, hysteresis/recovery samples and cooldown. Config example includes worker evidence, backlog, health-score and failed-task digest (`config.operator.example.json:14–103`). Incident/delivery/watch APIs in `server.py:215–245`; optional profile/config required (`compose.operator.yaml:1–9,86–105`). No activation state inferred.
- **External watchdog already exists:** `deploy/operator/watchdog.py:66–145` checks supervisor heartbeat<=120s, delivery pending/deadletter/uncertainty/age and gateway, with two-sample activation/recovery and direct Telegram transport. Documentation says another host (`docs/technical/hermes-operator-release.md:209–215`). It does not test audio/provider correctness. Unknown installation/last-success/delivery until C0 probe.
- **Readiness is not a playback SLI:** API/readplane healthchecks in base compose; worker/projector own-role progress<=45s plus PG/Redis readiness only in operator overlay (`compose.operator.yaml:177–262`, `app/crate/role_readiness.py:32–69`). Frontend probe fetches `/`; media-worker probe can queue behind synchronous packaging. Record exact enabled compose overlays per installation.
