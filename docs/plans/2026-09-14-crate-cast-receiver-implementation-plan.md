# Crate Custom Cast Receiver Implementation Plan

> **For agents:** REQUIRED SUB-SKILL: Use
> `viterbit-ai-tools:executing-plans` to implement this plan task by task and
> `viterbit-ai-tools:test-driven-development` for every behavioural change.

**Goal:** Replace the Default Media Receiver with a production-ready Crate
receiver that owns an autonomous queue, reflects remote playback in Listen,
works from Web and Capacitor, and renders a real time-indexed spectrum.

**Architecture:** CAF remains the media engine and source of truth for playback.
An authenticated sender creates a scoped playback session, transfers the full
queue to CAF, and then edits it through revisioned commands. The receiver is a
small React/Vite application with an isolated CAF adapter; React owns discrete
state while progress and spectrum update imperatively. Spectrum artefacts are
generated by a governed worker and exposed only through the playback-session
lease.

**Tech Stack:** React 19, TypeScript, Vite, Vitest, Cast Application Framework,
Canvas 2D, FastAPI, Pydantic v2, SQLAlchemy Core, Alembic, Dramatiq, PostgreSQL,
Sentry, Capacitor Google Cast SDKs, Docker, GitHub Actions.

---

## Delivery invariants

- Preserve the existing single-track Cast ticket flow as an automatic fallback
  until the custom receiver rollout is explicitly enabled.
- Never expose a user bearer token or unrestricted API route to the receiver.
- The API remains read-only with respect to the music filesystem; any spectrum
  or receiver-safe derivative write happens in a worker.
- When Cast is active, CAF/receiver status is authoritative for current item,
  time, play state, buffering, volume, repeat and queue ordering.
- Disconnect leaves playback running; Stop Cast stops playback and revokes the
  lease.
- Queue mutations are monotonic and idempotent. A stale sender adopts receiver
  state before retrying one user intent.
- A missing spectrum never blocks playback.
- Web, Android and iOS share the same protocol fixtures and semantics. Tauri is
  explicitly unavailable in this release.
- Every cut is test-first, independently committed, pushed, and followed by the
  relevant tests, typecheck/lint/format, React Doctor and build checks.

## Definition of done

- All automated gates are green with React Doctor clean.
- Both receiver app IDs resolve to the expected versioned build.
- Web, Android and iOS pass the hardware matrix.
- Receiver owns and continues the complete queue without a connected sender.
- Listen accurately reflects receiver progress and controls.
- The TV renders branded skins, artwork, metadata, queue and synced spectrum.
- Revocation, expiry, CORS, Range and telemetry redaction are verified.
- The release can fall back to the Default Receiver without a database rollback.
