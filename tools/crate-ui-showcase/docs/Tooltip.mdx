<DocHeading as="h2">Contract</DocHeading>

Actual Radix tooltip provider/trigger/content with a governed portal, named trigger, focus/hover, side offset and Escape. Tooltip describes an existing control; it never replaces its accessible name or becomes a mobile-only source of required information. Focus does not open a tooltip when the last interaction was a pointer, so a dialog or panel that moves focus onto a trigger after a click does not leave its tooltip open; keyboard focus still opens it. On screens without hover, focus opens a tooltip only after the keyboard has been used, so a sheet that focuses its close button on a phone does not show a tooltip. The rule lives in `lib/input-modality`, which modal focus shares: on a touch-only screen without a keyboard, modals focus the dialog itself instead of its first control, so no focus ring appears when a sheet opens or the screen wakes.

The approved mockup and Diego's later amendments are the visual reference. This entry documents actual existing components; native device, assistive technology and complete consumer certification remain separate. No production requests, credentials or persistent preference writes occur here.

<DocHeading as="h2">Primary and tooltip review amendment</DocHeading>

TooltipHint adapts legacy title metadata to the existing Tooltip recipe without adding a layout wrapper or changing the native control. It preserves refs and handlers. An outer Tooltip owns nested descriptions, preventing duplicate custom tooltips; no DOM title is emitted. Empty hint content adds no text, tab stop or dangling description. Escape closes the hint even when an active drag has already consumed that key, so the next Escape can close the containing editor.
