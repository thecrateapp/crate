<DocHeading as="h2">Form typography roles</DocHeading>

All field captions use MonoLabel (Mono 400, uppercase, 11/15.4 px), including inline Checkbox, Switch and RadioGroup options. Inline is a layout choice, not a different typographic role. Helpers/errors use Mono 400 at 11.5/16.1 px. Editable controls and ordinary readonly output use the brand body face at 400, 15/21 px. Filters and segmented modes use Mono 400 at 12/16 px. Readout keeps its contextual Mono role; StatNumber uses display numerals and a normal-weight Mono caption. Surrounding headings or bold text must not change these defaults.

Native brand-font exceptions remain resolved through the existing font variables. General form ranges now use Slider in both apps; playback and EQ retain specialized controls.

Radio choices reserve their 44 px coarse hit areas without overlap. Long searchable options wrap inside the menu. FormField kind="group" provides the caption and ARIA association without a native label target on a non-labelable group. Existing preview fixture controls use these same components; no new mockup specimens are added.

The actions catalogue now includes Solar Eye Outline for preview actions. ActionButton/ActionLink compose the existing Button recipe; IconButton keeps the compact round/glow role. Coarse targets reserve at least44px in layout.

## Surface roles — 1AT

Canvas is the app background. Card is an opaque standalone object on surface-object with a quiet border and14px panel radius. InstrumentPanel is an unfilled section/figure with a quiet top rule,22px top inset and20px header rhythm. Separator is a1px subtle sibling rule. Artwork controls use the same opaque object surface, without a blur or cast shadow; their geometry and semantic states are independent. Modal/popover/scrim layers retain their dedicated contracts. Do not use Card as a generic replacement for every panel.
